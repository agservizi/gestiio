ORM API / Pickup API - Ordini Ritiro Merce
-----------------------------------------

Protocolli
~~~~~~~~~~
* HTTP 1.1 / REST
* HTTP 2 / REST

Utilizzo
~~~~~~~~
* API Key: Header HTTP con chiave 'X-Api-Key' e valore l'API Key staccata in fase di sottoscrizione.

Inserimento
~~~~~~~~~~~

^^^^^^^
La request rappresenta l'input generico di Geopost con l'aggiunta di campi specifici per la Business Unit BRT (vedi `brtSpec`).

Peso e volume
^^^^^^^^^^^^^
Il peso è un dato obbligatorio ai fini della richiesta. È possibile specificarlo, in alternativa, in tre modi:

* `brtSpec.weightKG`: peso totale dei colli/bancali in chili
* `mpsWeightAndDimension.weight.value`: peso totale dei colli/bancali in grammi
* `parcelInfos[].declaredWeight.value`: peso per collo/bancale in grammi

Uno di questi deve essere obbligatoriamente presente (per collo/bancale devono essere specificati tutti). Si consiglia l'utilizzo di `brtSpec.weightKG`.

Il volume non è obbligatorio. La sua eventuale valorizzazione segue analogamente quanto già descritto per il peso:

* `brtSpec.volumeMC`: volume totale dei colli/bancali in metri cubi
* `mpsWeightAndDimension.dimensions.length`, `mpsWeightAndDimension.dimensions.width`, `mpsWeightAndDimension.dimensions.height`: le dimensioni totali, in metri, dei colli/bancali
* `parcelInfos[].dimensions.length`, `parcelInfos[].dimensions.width`, `parcelInfos[].dimensions.height`: le dimensioni, in metri, per ogni singolo collo/bancale

Fresh
^^^^^
Per richiedere un ritiro di tipo Fresh è necessario:

* valorizzare `brtSpec.serviceCode`: "B20"
* indicare il dettaglio dei colli/bancali con relative date di scadenza

Response
^^^^^^^^
Anche la response, ovviamente, è un array: _[{..resp. ordine 1..}, {..resp. ordine 2..}]_. Di seguito il dettaglio:
[options="header,footer"]
|=======================
|Field name|Field description
|ormReservationNumber|Numero prenotazione ritiro
|sendingDepot|Filiale di partenza
|collectionDate|Data di ritiro applicata
|serviceTime|Orari di servizio
|commissioned|Commissionato
|parcels|Elenco dei colli/dettagli
|errors|Errori (vedi sezione Errori)
|=======================

Errori
^^^^^^
Gli errori sono gestiti in base al numero di ordini inseriti:

* Ordine singolo (un solo oggetto nell'array della request): l'errore verrà restituito come errore HTTP:
[source,json]
-----------------
{
 "timestamp": "2023-11-07T10:20:36.430489744",
 "status": 400,
 "error": "Bad Request",
 "message": "Message...",
 "path": "/api/geodata/v410/colreqs"
}
-----------------

* Più ordini: gli errori per l'ordine che li ha causati sono indicati nel campo `errors`

In entrambi i casi, se ci sono errori di validazione (es. formato date, incongruenza campi, ...) viene restituito subito un errore HTTP.

Cancellazione (solo per ORM Fresh, B20)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Request
^^^^^^^
La request, senza body, prevede la valorizzazione del numero prenotazione ritiro nel path (sostituendo {id}):

- /api/geodata/v410/colreqs/{id}

Response
^^^^^^^
true/false
